# 长距离贴墙场景压力测试

测试脚本：`scripts/test_wall_hugging.py`（模型 = `ellipse_net_best.pt`，epoch 20，test 集 = 3 个未见地图组）

```powershell
& E:\CondaEnvData\envs\GGMPC\python.exe scripts\test_wall_hugging.py --part both --n-maps 4 --n-paths 3
```

* **Part A**：在现有 test 集里按"到最近膨胀障碍的距离"分层，并单独挑出"连续 ≥8 个采样点
  净空 ≤3 cells"的长贴墙段。
* **Part B**：在 4 张**未见**测试地图上主动制造贴墙轨迹——因为单纯给 A* 加"偏好贴墙"的代价
  在开阔街道网格上不划算（绕路不付代价），改为先检测**真正细长的窄通道**
  （clearance ≤3 cells 的连通域，主轴长度 ≥60 cells 且 ≥2.5×短轴），在通道两端取起终点，
  再对"离开通道"的栅格加大代价，得到贴墙比例 100% 的路径，最后走**真实标签流水线**
  （固定中心 IRIS + ρ≤0.9 + 连续几何安全判定）。

## 结论

1. **贴墙是明确的失效区**：安全率从开阔区 0.845 掉到 0.315，真·窄巷只有 0.147。
2. 但**中心误差反而更小**（0.28 m vs 0.53 m），说明问题不在"放哪"而在"多大/多胖"：
   贴墙段半轴 a 误差 1.28 m，网络把细长走廊椭圆画胖了，一旦胖出墙即判为碰撞。
3. 方向误差在开阔区反而大（29.9°）——那里椭圆接近圆，角度本身不可辨识（与 `angle_valid`
   的设计一致）；贴墙段只有 5.6–10.3°，说明网络能抓住走廊走向。
4. **数据侧同样稀薄**：整个 test 集 540 条路径里只有 10 条含 30 cells 以上的连续贴墙段
   （共 137 个样本）。主动构造的窄巷里标签产出率也偏低（5/32、13/131、19/172、215/433）：
   1–2 cell 宽的巷道在 `min_semi_axis = 0.5 m` + `ρ ≤ 0.9` 的规则下，很多路径点确实不存在
   合法的安全椭圆——这是几何事实，不是 bug，也不应放宽标准。
5. **安全投影是低成本兜底**：收缩后安全率 100%（构造性保证），代价是面积：
   窄巷平均缩到 0.77、开阔区几乎不缩（0.986）；IoU 只掉 0.03（0.531→0.503），
   贴墙段 0.626→0.669 反而略升（收缩后更贴近真值细长椭圆）。
