| 射线终点/中点几何 | `p + (d−0.15)·u` 只有 9.8% 落在 blocked 格 —— 正因为 `d` 是到达 blocked 格**边界**的距离（见下）；中点落在 free 格的最低比例 0.746（集中在 16 条射線全量程截断的开放区） |

射线语义（重要，决定了候选中心公式里的 `m`）：`pipeline._cast_one` 返回的是
“沿射线走到**第一个 blocked 格边界**的距离”。用 21×21 手构地图验证：从 col 5 向 +x 打到
col 10 的墙，返回 4.5 格 = 墙格左边界。因此 LiDAR 量程本身就是“点机器人沿该方向能走多远”，
`blocked` 里已经包含了机器人半径 + 安全余量，候选中心公式里的 `m` 只能是数值裕度
（本实现取 `candidate_ray_margin_m = 0.01 m`），**不能**再扣一次机器人半径。

## 4. Task 2：距离场数据版本

### 4.1 约定（`ellipsenet/data/sdf.py`，`data/distance_fields/manifest.json`）

- 自由区：`+距离到最近 blocked 格“面积”`；blocked 区：`−距离到最近 free 格“面积”`；

## 5. Task 3–7：网络实现（逐条对照方案）

张量记法：`B` batch、`N` 路径点数（padded）、`R = 16` 射线、`C = 128`。

### 5.1 两个独立 ResUNet（方案 3）

```
Occupancy (B,1,256,256) → ResUNet_occ  → F_occ  (B,C,256,256)
SDF       (B,1,256,256) → ResUNet_dist → F_dist (B,C,256,256)
```

- 结构相同、**参数完全独立**（两个 `ResUNet` 实例，无共享、不拼接输入）；
- 编码器 stem(base=24) → /2(48) → /4(96) → /8(192) 瓶颈，解码器双线性上采样 + 同尺度 skip + ResBlock，最后一层 1×1 卷积输出 `C=128`，输出尺寸 = 输入尺寸；
- SDF 输入按固定 `d_clip = 8 m` 裁剪归一化（`clamp(S/8, −1, 1)`），逐图 min-max 归一化已明确禁用；
- 对齐由 `tests/test_alignment.py` 验证：脉冲输入 → 输出能量峰仍在同一像素、响应质心在同格内；格中心查询精确命中本格、隔一格为 0、半格为双线性均值；
- 地图外查询返回 blocked 常数而不是钳到边界值。

### 5.2 Occupancy 9 Token + 相对位置编码（方案 4）

构造 `3×3` 物理间距 0.5 m 的 9 个查询坐标（写入配置，不随分辨率变化）：

```
x_ik = p_i + Δ_k                       (B,N,9,2)
m_ik = GridSample(F_occ, x_ik)         (B,N,9,C)
e_ik = MLP_pos(Δ_k / 0.5)              (9,C)
z_ik = MLP_token([m_ik, e_ik])         (B,N,9,C)
c_occ = MLP_occ(Flatten(z))            (B,N,C)
```

相对位置编码在 **Flatten 之前**逐 Token 加入（消融开关 `ablate.occ_pos_encoding` 可移除）。
这里没有 Attention，只有坐标查询 + MLP。

### 5.3 射线特征与点-射线 MLP 融合（方案 5）

```
e_dir  = MLP_dir([cosθ, sinθ]) + slot_embedding[16]        (B,R,C)
x_ijk  = p_i + λ_k · d_ij · u_ij,  λ ∈ {0.25,0.50,0.75}    (B,N,R,3,2)
m_ijk  = GridSample(F_dist, x_ijk)                         (B,N,R,3,C)
s_ijk  = S(x_ijk)   可微双线性，图外 = −1 m                  (B,N,R,3)
c_ray  = MLP_ray([m_ij1,s_ij1,λ1, m_ij2,s_ij2,λ2, m_ij3,s_ij3,λ3, d_ij, e_dir, ray_valid])
r_ij   = MLP_fusion([c_occ, c_ray])                         (B,N,R,C)
```

角度编码保留真实角度，槽位 Embedding 只作为可学习附加项；**没有点-射线 Cross-Attention**。

### 5.4 两级交互（方案 6–8）

```
R̂  = Transformer_ray(R)                2 层 / 4 头 / Pre-LN / FFN 2C，仅在同一个点的 16 条射线内
h_local = MLP_point([c_occ, Flatten(R̂)])   (B,N,C)          ← 17C = 2176 维输入
s_i  = 归一化弧长 ∈ [0,1]（padding 不拉伸）
h    = h_local + PE(s_i)               正弦位置编码
H    = Transformer_path(h, key_padding_mask=¬mask)         2 层 / 4 头 / Pre-LN / FFN 2C
```

不加入路径切向、不加入旧 `clearance`、不加入人工中心偏移；Path Attention 的 Token 就是完整点特征。

### 5.5 输出头与 16 个候选（方案 9）

```
π_i   = softmax(dir_head(H)/τ) ∈ Δ^15           (B,N,16)
α_i   = σ(ratio_head(H)) ∈ (0,1)                (B,N)
a_i   = a_min + (a_max−a_min)·σ(·), a_max = 6 m (B,N)
b_i   = b_min + (a_i−b_min)·σ(·) ∈ (b_min, a_i)
θ_i   = atan2(pred_sin, pred_cos)               周期安全，无角度跳变
q_ij  = p_i + α_i·max(d_ij − m, 0)·u_ij         (B,N,16,2)
```

`π` 用 softmax（τ 1.0 → 0.7 缓慢退火），**没有 Cross Entropy、没有 Gumbel、没有人工方向标签**。
测试断言：候选中心严格位于各自射线上（叉积 < 5e-7）、只沿射线正向、偏移长度 = `α·max(d−m,0)`；
`a ≥ b > 0`、`a ≤ a_max`；`α ∈ (0,1)`；模板点 `ρ ≤ 1` 且能触到边界；推理 `argmax` 取真实候选
（绝不做 `Σπ q` 加权平均）。

### 5.6 参数量与实现注记

5.04 M 参数（`C=128`、`resunet_base=24`）：两个 ResUNet 各 1.579 M（3.16 M），
Ray/Path 两个 Transformer 各 0.265 M，`point_mlp` 0.590 M（输入 2176 维），
`occ_mlp` 0.328 M，`ray_mlp` 0.166 M，`fusion_mlp` 0.099 M，三头与位置/方向编码为余量。
形状头与比例头做了**有界初始化**（初始 `a≈1.5 m, b≈1.0 m, θ≈0, α≈0.3`）：
默认初始化会把 `b` 压到 `b_min=5 cm`，两个相邻 5 cm 椭圆的连接损失量级会飙到 1e2 以上，
把训练一开始就推向错误方向；这是标定阶段实测到的现象（见 6.2）。

## 6. 损失与权重标定（方案 10 / 11）

### 6.1 损失项

```
L_ij(local) = w_d·(−min(max(S(q_ij),0), D_max))            D_max = 8 m
            + w_s·mean_k[max(0, d_margin − S(x_ijk))]²      d_margin = 0.06 m
            + w_a·(−log(π a_i b_i + ε))
L_choice = mean_i Σ_j π_ij L_ij
L_conn   = mean_i Σ_j Σ_k π_ij π_i+1,k [双向边界覆盖惩罚]
L_total  = L_choice + w_conn·L_conn / scale_conn
```

椭圆采样模板（标定后）：半径 `[0, 0.5, 0.8, 0.95, 1.0]` × 点数 `[1, 6, 10, 16, 24]` = 57 点，
覆盖内部、内部环、近边界与边界；连接损失在两侧边界各取 8 点、对 16×16 候选对双向计算。

### 6.2 记录原始量级后做尺度归一化（方案 10.7）

实测原始量级（阶段 B 首步 / 稳定段）：`clearance(−S)` ≈ −2.4 → −3.6、`safety` ≈ 1e-3–0.2 m²、
`−log(area)` ≈ −1.7 → −3.6、`conn` ≈ **1.2e2 → 6**。据此定 `configs/v3.yaml` 的
`loss.scales = {dist 1.0, safe 0.02, area 1.0, conn 100.0}` 与
`w = {w_dist 1.0, w_safe 5.0, w_area 0.05, w_conn 1.0}`，
即“安全项放大 250 倍、连接项缩小 100 倍”，使选择项与连接项量级可比（选择项 −3…−5，
连接项 0.06–1.2）。续训 C2 在此基础上把安全项再放大 2.5 倍、面积项乘 0.6。

同时记录的诊断量（`log.csv`）：`raw_dist / raw_safe / raw_area / raw_conn / s_center_mean /
area_mean / pi_entropy / pi_max`，以及验证集的净空、面积、精确安全率、连续覆盖率、越界率。
注意 `raw_safe/raw_conn` 是**对 16 个候选的朴素平均**（衡量损失地形），
而 `choice` 是 π 加权后的目标，两者含义不同（训练日志中前者持续上升而后者的项不涨，
是因为模型把概率集中到了安全候选上）。

### 6.3 方向头为什么能被训练（方案 11）

`dL/dl_ij = π_ij/τ (L_ij − Σ_k π_ik L_ik)`，由 `test_losses.py` 数值验证：
解析式与 autograd 最大误差 7.5e-9，且 `logits.grad · (L_ij − <L>) > 0` 逐元素成立
（代价低于期望的射线 logit 上升）。第一阶段只使用概率加权期望，没有额外稳定项。

| `w_span=0.75`，lr 1e-5 | 2 epoch（提前停） | 0.989 | **0.710 / 0.688** |
| **对照：`w_span=0`，其余相同**（lr 4e-5，4 epoch） | 4 epoch | 0.976–0.979 | 0.873 / 0.895 / **0.909** / 0.878 |

读法：
- 对照组说明“多训几轮”本身就能把连续性从 0.963 抬到 0.976–0.979，安全率只掉 1–5 点；
- 加了 `w_span` 之后连续性再涨 1 点，但安全率塌 20–40 点，而且**降 lr、降权重都救不回来**；
- 原因：要让中点落进两个椭圆，只有两条路——把椭圆长大，或把两个中心拉近，**两者都直接抵消安全项**。
  因此 `w_span` 在配置里保留但默认 **0.0**（`loss.w_span`）。

#### 9.6.3 尝试二：相邻站点偏移连贯项（`w_smooth`）——成功，已设为默认

`Delta_i = q_i − p_i` 是每个站点选定的偏移向量（对 16 个候选按 π 加权）。相邻链条断裂的真实
病根是**相邻站点选到相反方向的射线**，于是加：

```
L_smooth = mean_i || Delta_i − Delta_{i+1} ||^2        （仅用 path_xy 与预测，零标签）
```

它只作用于方向分布与比例 α，不奖励更大的椭圆，因此不动净空。

读法与结论：

- **5 安全损失是碰撞的唯一支柱**：去掉后精确安全率从 0.893 掉到 0.029，

- **2 去掉 Ray Self-Attention 代价极大**（0.893 → 0.369）：同一点 16 条射线的上下文
  对“这条射线是否可信、该走多远”是必需的，否则形状与方向脱节（面积涨到 22.7 m²）。

- **8 加权期望 vs 离线 oracle**：同一 checkpoint，用单点最小代价候选替代 argmax

说明“600 步就学到头”只对短预算成立，低 lr 阶段仍有 +6 点的空间。

## 11. 已知局限与下一步（不掩盖问题）

1. **目标函数与 GT 语义不同**：训练目标只有“中心净空更大 + 椭圆更大 + 不撞 + 相邻不脱节”，
   没有任何“贴着路径”的约束，因此学到的解是“往开阔处推、把椭圆撑到接近 6 m 上限”。
   这解释了 GT 中心误差中位 3.3–3.9 m、GT IoU 0.27–0.33、面积比 p50 1.3–1.4。
   若需要“沿路径的安全走廊”语义，应加入 GT-free 的额外项（例如中心到路径的软约束、
   弧长间隔相关的连接要求），但这属于方案之外的改动，本次没有擅自加入。
2. **精确碰撞率：长训后 5.45%（测试集），仍有 1/20 的椭圆越界**：中心碰撞率只有 2.1e-4，
   碰撞几乎全部来自**椭圆尺寸/朝向**，且集中在窄通道。10k×50epoch 把这一项从 12.95%
   压到 5.45%（中心净空 p10 0.97 → 2.23 m），继续压的旋钮是：加大 `w_safe`、
   把 `d_margin` 与采样密度按椭圆曲率自适应、或对 `a_max` 做与当地净空相关的封顶。
3. **边界互相包含覆盖率 0.43–0.44**（长训没有改善）：中点连续性（0.96）掩盖了这个问题；
   连接损失是“边界采样 + 平方惩罚”的近似，λ_c 提高会进一步压低它，但也会压制面积增长。
4. **方向分布过尖**：熵 0.04–0.07、最大概率 0.97，训练第 100 步附近就塌缩；
   方案 11 节预判的“概率不会自动变 one-hot / 期望低不代表 argmax 安全”都出现了。
   长训把 argmax 与最小代价候选的一致率从 0.20 提到 0.39–0.40，但离 oracle 仍有差距。
5. **训练预算/收敛**：40k×1ep（17.9 min）→ 10k×50ep（196 min）带来 +6.4 点验证安全率；
   60 次验证里有明显震荡（0.72–0.94），`best.pt` 落在 epoch 29 属于该均衡下的较好采样。
   early stopping 已按验证集几何指标实现（`exact_safe + 0.1·continuity`）；
   **多种子的方差仍未产出**（单次运行的 0.9455 有 ±1–2 点的不确定性）。
6. **未实现的方案项**：旋转/尺度增强（只做了翻转；旋转需要重采样地图与 SDF，
   方案要求“不要单独增强地图或射线”，本次保守只做翻转）；推理期投影安全层（方案未要求）；
   多尺度 map 特征（方案未要求）。

|---|---|---|

## 15. 凸区域生成（椭圆 → 多面体，借鉴 Neural-IRIS）

方案之外的新增能力：把每个预测椭圆"吹成"一个凸多面体（半空间交），供 MPC/规划器直接使用。
实现在 `ellipsenet/geometry/polytopes.py`，测试 `tests/test_polytopes.py`，
端到端示例 `scripts/build_convex_regions.py`。

### 15.1 借用的方法与三处改进

Neural-IRIS（`Neural-IRIS/src/neural_iris/safe_region.py`）的做法：在**局部 patch** 上取障碍
边界点，按椭圆二次型距离 (x−c)ᵀQ(x−c) 升序贪心，为每个点加一条分离超平面
n = Q(obs−c)/‖·‖、b = n·obs − margin，并把已被该平面排除的点过滤掉，最后加 patch 四边。

本实现保留骨架，改动三处（前两处"更准"，第三处"更快"）：

1. **障碍按方格处理，平面放在近端面** `b = n·o − h(|n_x|+|n_y|) − margin`（h = r/2），
   而不是 `n·obs − margin`。早期误用远端支撑（`+h`），平面会切进方格，实测转角处漏出约
   2 cm —— 已修正并被测试锁定。
2. **精确重叠判定**：方格与多面体相交 ⟺ 方格四角有角点落在多面体内，或（区域极小以致
   完全落在某个方格内时）区域顶点落在方格内。两者都是闭式，不需要采样。
3. **单一精确循环 + 方向种子**：先用 8 个角扇区各补一条平面（等价于 V2 的 32 扇区初始化，
   但整批一次算完），再让精确循环收尾。循环的**终止条件本身就是验收**——不存在一个可能与
   构造不一致的独立"检查 pass"。

### 15.2 为什么必须有验收（实测）

贪心若只用"整格包含"判定，只认完全落在区域内的方格，**漏掉只把一个角伸进区域的方格**。
30 个椭圆的样本上实测：

| 配置 | 全图精确复检 | 时间 |
|---|---|---|
| 只有贪心，不做精确判定 | **12/30 区域含障碍格（47 个格子）** | 6.9 ms |
| 精确循环（当前实现） | **0/30** | 9.2 ms |

更早的「cheap 贪心 + 有限轮 repair」拆分在 12 条轨迹（302 椭圆）上留下 16/302 违规区域——
拆分不收敛，因此改成了单一精确循环。

### 15.3 并行与"只做局部"

- 一批椭圆共用一组向量化 kernel（`build_polytopes`），没有逐椭圆 python 循环；逐椭圆的
  `build_polytopes_serial` 只用于测试参照。
- 每个椭圆只用自己周围的窗口：`窗口半径 = 半长轴 + window_margin_m`（默认 3.0 m），
  4 张窗口面作为硬平面加入 → 区域必然落在窗口内，验收只需看窗口内的格子。
- 窗口内先把**障碍格压缩**成候选集（真实场景窗口里只有约 4% 是障碍：实测 214/5929），
  之后每次判定都在候选集上做。

### 15.4 实测（RTX 4070，test 划分）

| 指标 | 数值 |
|---|---|
| 端到端（预测→区域），8 条轨迹 / 202 椭圆 | **18.0 ms / 轨迹，0.71 ms / 椭圆** |
| 同一张地图 256 个椭圆一次批量 | **41 µs / 椭圆**（10.5 ms 总计） |

### 15.7 为什么不是"每个椭圆一次性给几条约束"

"每个椭圆一套独立约束"这件事本来就是这么做的（一批椭圆并行算）。区别只在于**要不要去冗余**
和**要不要收尾**。同一批 4 个椭圆（窗口内 129-842 个障碍格）三种做法：

| 做法 | 约束条数 | 面积 | 区域内含障碍格 |
|---|---|---|---|
| (a) 窗口内每个障碍格各给一条约束 | 137-850 | 192-307 m2 | 0 |
| (b) 去冗余（本实现） | **8-16** | 199-300 m2 | 0 |
| (c) 只做 8 方向种子，不收尾 | 16 | 199-300 m2 | 0（这 4 个椭圆碰巧不需要收尾） |

(a) 与 (b) 安全性相同、面积几乎相同，但约束条数差 10-50 倍：几百条约束送进 MPC 的 QP 会直
接把每帧求解拖垮，所以"每格一条"不可用。(b) 里那个"贪心"不是参数搜索，就是**去冗余的规则**：
按椭圆度量 (x-c)T Q (x-c) 从近到远看障碍格，**已经被现有平面挡住的就跳过**。

在 12 条轨迹 / 302 个椭圆（真实非对称地图）上，一次性到底够不够：

| 配置 | 违规区域 | 时间 |
|---|---|---|
| 只做 8 方向种子（`refine=False`） | **110 / 302** | 4.1 ms / 轨迹 |
| 种子 + 精确收尾（默认） | **6 / 302**（全部属于自身碰撞的椭圆，几何无解） | 8.5 ms / 轨迹 |

**34%（104 / 302）的椭圆需要收尾**——它们的方向扇区夹角处有方格伸进区域。这就是为什么默认
保留精确收尾：一次性的 16 条约束在开阔处够用，在拥挤/夹角处不够。想更快可以用
`refine=False`（省一半时间），但要接受约 1/3 的区域会切到障碍。

### 15.8 边构建边剔除障碍点（照抄 Neural-IRIS 的 C++ 内核）

Neural-IRIS 的 Python 版是逐点过滤，C++ 版（`cpp/src/geometry2d.cpp: build_safe_halfspaces`）
把它做成了**增量活动集**：

```cpp
while (!active.empty()) {
    const Point2 obs = active.front();                  // 最近的障碍点
    ... 计算 n_hat, b_val 并加入 A/b ...
    for (size_t i = 1; i < active.size(); ++i)           // 剩余点只扫一遍
        if (n_hat * p <= b_val + 1e-3) next_active.push_back(p);   // 被这条平面挡住的留下
    active.swap(next_active);                            // 集合单调收缩
}
```

本实现改成同样的结构，但**方格**要比点多半步：区域包含一个方格的条件是"**同一个角**满足
所有平面"（一个角伸进来就已经算碰撞）。所以对每个候选格维护 4 个角的**累计最大违反量**
`slack (N,M,4)`：

- 加一条平面：`slack = max(slack, n·corner − b)` —— 只扫一遍剩余候选，历史平面不重算；
- "这个格子还在区域里" ⟺ `min over corners of slack ≤ 0`；
- `active` 为空 ⟺ 没有障碍格有角落在区域内 ⟺ 验收通过（循环终止条件即验收）。

算量从"每轮重算 P 条平面 × 全部候选 × 4 个角"（`O(轮数·P·M)`）降到"每条新平面扫一遍剩余候选"
（`O(平面数·M)`）。

| 指标 | 重算版 | 增量版（现在） |
|---|---|---|
| CPU 批量 256 椭圆 | 346 µs / 椭圆 | **109 µs / 椭圆**（3.2×） |
| GPU 批量 256 椭圆 | 46 µs / 椭圆 | **46 µs / 椭圆**（启动延迟受限，不变） |
| 12 轨迹 / 302 椭圆 | 0.35–0.39 ms/椭圆 | **0.39 ms / 椭圆**（9.9 ms/轨迹） |
| 安全（可行且自身安全） | 0 违规 | **0 违规** |
| 区域面积 p50 | 263–274 m² | 274 m² |

两个必须记住的坑（都踩过并被测试/校验抓住）：

1. **增量过滤要"同一个角"**：如果按"每个平面各自有角在内侧"更新，活动集是真正违规集的**超集**，
   平面预算会被浪费在并不违规的格子上，最后反而漏掉真违规（实测 1 个可行椭圆残留 163 个违规格）。
2. **不可行判定不能用带留边的偏移**：`offset` 已经减去了 2 cm 区域留边，"平面切到椭圆"应当拿
   **减去留边之前**的近端面去比；否则"贴着障碍但确实安全"的椭圆会被误判无解并提前放弃（同一
   个 163 格漏洞的成因）。改成 `support > face` 后，该椭圆正常收敛。

方向种子默认关闭（`seed_directions=0`）：12 轨迹样本上它把耗时从 8.8 抬到 15.8 ms，只把"原始违规"
从 10 降到 6（这 6 个仍是自身碰撞的椭圆），不划算；留作可选（配合 `refine=False` 就是"一次性给完
约束、完全不迭代"的模式）。
